# Opt-in project execution, publication and research

These tools extend the existing runtime, worker, project registry, and approval queue. There is no new migration, runner service, or default production enablement. Use Node 22 for both web and worker. See [dependency audit](dependency-audit-2026-11-20.md) for the Next upgrade and outstanding findings.

## Worktree and presets

1. Use a **disposable non-production worker/VM**, a dedicated non-root identity, no shared-tenant data, and a private staging copy (`0700`, owned by the worker) outside the app's checkout. No other service or user should modify the directory or its ancestors while the worker can use it. Set `AGENT_EXEC_ROOT`, `AGENT_EXEC_WORKSPACE_ID`, and `AGENT_EXEC_PROJECT_ID`. Only a durable job for that exact project/workspace, submitted by a current admin or owner, sees the tools. One configured worktree per worker environment; there is no checkout creation, cross-project mount, or Git CLI passthrough.
2. `project_file` lists allowed entries or reads small UTF-8 files and their hashes. `project_edit` creates in existing directories, replaces using the previous SHA-256, or applies one uniquely matching text replacement. No delete, recursive edits, or binary content. Dot paths, common credential filenames, dependencies, special files, links, hard links, and unsafe directory ancestors are denied. A root-wide lock serializes app edits. Scope is based on private ownership and must not be used as a filesystem boundary against concurrent host writers with the same UID. The name filter is not secret detection: **stage only reviewed non-secret material**. A host interruption can leave `.xirel-write-lock`; confirm there is no active writer and reconcile file hashes before clearing it or restoring the staging copy.
3. Leave `AGENT_EXEC_ENABLE` unset until `npm run test:sandbox` passes on the intended Linux worker image. Test requires unprivileged user namespaces, `unshare`, `mount`, `chroot`, `setpriv`, and `prlimit`. If using the tested launcher, enable `namespaces` and list exact presets in `AGENT_EXEC_PRESETS`. `node-test` runs `node --test`. The two npm presets require `AGENT_EXEC_PACKAGE_SHA256` from the **reviewed** `package.json`; `npm --ignore-scripts run test/build` skips implicit pre/post scripts. No install or arbitrary command/argument tool. Projects can still execute code through approved test and build entry points. `AGENT_EXEC_MODULES`, if needed, must be a preinstalled, scrubbed, trusted read-only dependency tree. Do not bind a general package cache or the app's dependencies.
4. The runner copies bounded text into a private snapshot and then a disposable 96 MiB tmpfs. Namespace, network, PID, mount, and capability controls, sanitized environment and capped wall time (30 seconds from launch), stream output (24,000 combined bytes) and process resource limits apply. The audit row is written before spawning and updated with status, exit code and captured stream sizes; stdout/stderr are returned within the tool turn for diagnosis, not stored verbatim in tool audit. The host staging copy is not mounted into the command process. Failed setup never falls back to a host command. `test:db` includes a real namespace-backed worker test, so its full integration suite also requires this Linux setup.

**Not a hardened multi-tenant sandbox:** the command host kernel and a read-only host `/usr` remain in the trust boundary. The isolated `/proc` can reveal some host/kernel metadata, and process rlimits and tmpfs are not substitutes for cgroup-wide CPU, memory, and PID limits. Use outer VM/container isolation and cgroup limits, keep `/usr` free of project data and credentials, and do not enable the launcher on a shared or production worker without a separate security review. The app's own production build was verified outside this optional runner; fixture builds inside it do not prove compatibility with every project, platform, dependency tree, or Render worker.

## GitHub review and publication

Reuse `AGENT_GITHUB_WORKSPACE_ID`, `AGENT_GITHUB_REPOSITORY`, `AGENT_GITHUB_REF`, `AGENT_GITHUB_SHARED_FILES` and a repository-scoped read token. Set GitHub token permissions for Contents: read and, if using check runs from a private repository, Checks: read. `github_inspect_commit` returns bounded changed-file metadata and truncated patches **only** for directly shared file paths, or the commit's check runs. No raw logs, past-page pagination, or automatic CI reruns.

Use a separate scratch repository with no deployment workflows or hooks for the first test. Add a separate fine-grained token restricted to that repository (Contents: write; Pull requests: write only if needed) and an allowed simple base branch via `AGENT_GITHUB_BASE_BRANCH`. Branch creation and opening a draft PR can trigger GitHub Actions; review those rules before even a staging write. This tool does not edit dot paths such as `.github/workflows`, modify existing refs, merge, or deploy.

Run edits and tests as one durable job. Submit publication as a **separate durable job**, with the exact repo, expected base commit, new `xirel/…` branch, file paths and SHA-256 hashes, PR title and draft choice. In **Command → Approvals**, a current admin or owner reviews the exact args and should independently verify each hash against the intended staged diff. Before approval there are no publication API calls. Resumption executes the server-stored action without a model reconstructing it, atomically consuming its bound receipt. It rechecks scope, base and file contents and creates a new tree/commit/ref and, optionally, a draft PR. Approval does not authorize changed content or software deployment. The two jobs are not a fully unattended multi-stage publishing pipeline.

GitHub writes are not transactional. If a request is interrupted or the branch exists but PR creation fails, review the persisted run and GitHub before any new approval. A tree/commit may exist without a branch, or a branch/PR may exist even if the network response was lost. Do not replay the receipt or assume a failed label means nothing happened. For rollback, unset the write token and have a human reconcile or remove staging refs after review.

## Web research

Configure Brave for one trusted workspace and exact public HTTPS `AGENT_WEB_PAGE_ORIGINS`. Search sends the query to Brave; do not use credentials or private project data in queries. Open approved URLs from the search results to get the title, bounded text, source URL, and retrieval time. The fetch pins a public IPv4 result, verifies TLS, sends no cookies/auth, refuses redirects and unsupported types/encodings, and enforces an eight-second deadline and a 320 kB body limit. The runtime labels retrieved text untrusted, asks the model to distinguish snippets from page evidence, and appends a server-tracked list of pages actually retrieved. This is not proof that every model claim is supported by a source. Pages requiring login, JavaScript, redirect, IPv6-only service, PDF parsing or browser automation are unsupported. No fallback bypasses those limits. If the staging environment uses enterprise CA roots, use the approved system trust store (e.g. Node 22 `NODE_USE_SYSTEM_CA=1`); never disable TLS checking.

## Optional OpenRouter configuration

`OPENROUTER_DEFAULT_MODEL`, `OPENROUTER_PLANNER_MODEL`, and `OPENROUTER_TOOL_MODEL` can select a chat model without changing provider priority or other providers. Unset preserves existing defaults. Tool-bearing requests and the JSON Schema provider method ask OpenRouter to require the routed parameters. Model identifiers and documented capabilities were checked against OpenRouter references; no authenticated inference was performed. Provider routes, context, quotas and prices vary and `:free` is not an uptime or price guarantee.

| Selection | Documented OpenRouter identifier | Use and caveats |
| --- | --- | --- |
| NVIDIA Nemotron 3.5 Lightning | [`nvidia/nemotron-3.5-lightning`](https://openrouter.ai/blog/insights/nemotron-3-5-lightning/) | Chat/tools; schema support depends on serving route. |
| Google Gemma 4 26B A4B | [`google/gemma-4-26b-a4b-it`](https://openrouter.ai/google/gemma-4-26b-a4b-it) | Chat, tools, structured output on documented routes; model supports multimodal input. |
| Google Gemma 4 31B | [`google/gemma-4-31b-it`](https://openrouter.ai/google/gemma-4-31b-it) | Chat, tools, structured output on documented routes; model supports multimodal input. |
| NVIDIA Nemotron 3 Nano Omni | [`nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`](https://openrouter.ai/nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free) | Documented multimodal input, text output and tools; do not assume JSON Schema. This integration uses the existing chat message shape. |
| NVIDIA Nemotron 3.5 Embed 1B | [`nvidia/nemotron-3.5-embed-1b:free`](https://openrouter.ai/provider/nvidia) | Separate [`/embeddings`](https://openrouter.ai/docs/api_reference/embeddings) interface; text inputs in this integration. |
| NVIDIA Nemotron 3.5 Rerank 8B | [`nvidia/nemotron-3.5-rerank-8b:free`](https://openrouter.ai/provider/nvidia) | Separate [`/rerank`](https://openrouter.ai/docs/api/api-reference/rerank/submit-a-rerank-request) interface; ranks text candidates. |

Embeddings and reranking are never routed to chat. Setting `OPENROUTER_RETRIEVAL_WORKSPACE_ID` and one or both retrieval model variables enables sending bounded project-memory excerpts and the objective to OpenRouter for admin/owner requests in that workspace only. Reranking takes precedence; otherwise embeddings are compared in memory. No vector store is created. If retrieval fails, recent memory is used and the run records the fallback. Enable only after the workspace approves external data sharing; unset the workspace variable to disable it.
