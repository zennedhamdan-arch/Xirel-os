# Autonomous runtime: implementation and rollout

This change extends the existing Next.js 15.5 / React 18 application and Node 22 Render worker. Supabase remains the identity and data authority; Drizzle and the existing queue, runtime, and command page are reused. Business OS code and its sales/payment RPCs are unchanged.

## Verified boundaries

- **Workspaces:** task and conversation reads are shared with members of the exact workspace. Continuation requires a current member role and task ownership, or an admin/owner role in that workspace. A reused task must match the submitted workspace and project. Both chat routes reject unauthorized input before touching chat history or invoking providers. Job and schedule controls require their requester or a workspace admin; approvals require an admin or owner. Global health probes require `GLOBAL_ADMIN_USER_IDS` and return sanitized status.
- **Browser versus service:** direct browser writes to agent state, projects, agent-related membership/configuration, and messages are revoked. Raw worker, approval, and audit tables are not served through the browser's Supabase role. Use the authenticated routes. Runtime SQL runs on the trusted server connection and still checks workspace/owner data. Keep the database service connection and provider keys server-side. For a private instance, restrict Supabase sign-ups and configure only trusted members; application auth does not replace an operator's Supabase enrollment policy.
- **Agent:** a bounded structured plan is persisted and then run in order. Hinted tools must actually run successfully. Project context and prior outcomes are provided as reference data. Verification re-reads the project row or file hash for their write tools and validates the isolated command exit status. Separate verification is not claimed for tools that lack a verifier. Provider calls honor the run deadline; tools are checked between operations. Local preset cancellation terminates the isolated process; cancellation of an external request does not undo a remote write. Chat is rate-limited per process; a reverse-proxy quota is recommended for production.
- **Durability:** one immutable occurrence key is written with the schedule advance in a PostgreSQL transaction. Worker claims use distinct ownership tokens; old claims cannot extend expired leases or finalize jobs. Job/task completion is atomic. Recovery can finalize an already-completed run without re-executing it. Interrupted or ambiguous writes are **not** automatically replayed. Read-only work can restart; general per-step continuation after a crash is not implemented. Cancel/pause fences future work but does not undo an in-progress effect. Review interrupted write jobs rather than re-submitting them blindly.
- **Approval:** versioned receipts bind workspace, job, requester, tool name and exact JSON arguments. Approve/requeue is transactional. Only a currently authorized reviewer can supply a usable receipt; a worker with a current lease can consume it once. Legacy name-only rows do not authorize execution. Pending decisions become stale after one hour; decided receipts have a one-hour consumption window. Approval cannot make an unavailable tool executable. Before adding any consequential tool, ensure its arguments identify an immutable target, keep secrets out of receipts, and implement provider-side idempotency/reconciliation.
- **Project work:** create projects, update descriptions, record typed memory with timestamps and provenance, and create prioritized work items from `/command`. An item can name an existing parent and one predecessor in the same project. A predecessor must be completed before the task can enqueue. This is not a general dependency-graph editor. Agent runs and queued results are linked to their project and inspectable from the timeline. The classic `/chat` surface remains available for reopening saved conversations.

## Connector configuration

Optional settings are in `.env.example`. Set them in the server environments of the web app and worker as needed, not in a browser variable or a project note. No credential is required to run the local database and route test suite.

- `AGENT_GITHUB_WORKSPACE_ID`, `AGENT_GITHUB_REPOSITORY`, `AGENT_GITHUB_REF`, `AGENT_GITHUB_READ_TOKEN`: opt into read-only GitHub metadata, branches, and recent commits. An optional comma-separated `AGENT_GITHUB_SHARED_FILES` permits reads of exactly those small UTF-8 files. Use one repository-scoped fine-grained token with Contents: read. File contents are sent to your configured AI provider. Use a pinned commit for immutable source, and never share files with secrets. Opt-in GitHub publication has a separate write token and exact approval requirement.
- `AGENT_WEB_WORKSPACE_ID`, `BRAVE_SEARCH_API_KEY`: opt into bounded Brave search with snippet and source URLs. Search queries go to Brave; do not enable it for workflows that must not send query data there. Public HTML/text retrieval is optional and origin-allowlisted; browser control is not available.
- Existing Gemini, Groq, Qwen and OpenRouter credentials remain server-side. No live providers or optional connectors were authenticated as part of the local tests.

See [optional project execution](project-execution.md) for staging-only worktrees, command presets, publication and model configuration. There is no arbitrary shell, SQL, or deployment connector. Isolate the worker environment and keep all optional tools disabled in production until their staging and security gates are met.

## Tests and change locations

`npm run test:db` uses throwaway PostgreSQL. It exercises the migration sequence twice, existing RLS/queue tests, and `scripts/test-app-integration.ts`, which runs the actual route handlers, Drizzle queries, worker, planner, and scheduler with substituted Supabase identity and AI/connector transport at the test boundary. It verifies denial before message reads, writes and AI calls, plan execution, actual project verification, deduplicated scheduling and work-item enqueue, exact approval and replay prevention, and interrupted write handling. `npm run test:logic` covers the existing pure functions.

- Authorization and API: `src/lib/api/guards.ts`, `src/lib/auth/redirect.ts`, `src/app/api/`.
- Runtime and connectors: `src/lib/agents/`, `src/lib/ai/`, `src/lib/connectors/`.
- Worker and data: `worker/`, `src/lib/jobs/`, `src/lib/schedules/`, `src/lib/projects/`, `src/lib/tasks/`, and migrations `0009`–`0011`.
- Personal workspace and monitoring: `src/app/(dashboard)/command/` and `src/app/api/projects/`.
